# R4 Backend Contract Reference

## Status

This document describes the locally implemented R4 database, DTO, and HTTP contract for command,
query, and UI consumers. Migrations `005` through `010`, the schemas under `src/contracts/r4/`, all
27 command routes, Human Query/search/export/import routers, and their handlers exist. Legacy Work
Item routes, response omission rules, event DTOs, and migrations `001` through `004` remain
compatible. R1-R4 formal gates and CI remain open; local implementation is not a phase-completion
claim. The latest recorded browser run passed 11 of 11 Chrome scenarios, but final named database,
backup, and aggregate R4 gate reruns remain pending at the current HEAD.

The generated machine inventory is [`openapi-r4.json`](openapi-r4.json). It is generated by
[`../script/generate-api-r4.mjs`](../script/generate-api-r4.mjs) from `COMMAND_ROUTES` and pure Zod
request schemas. [`openapi.json`](openapi.json) remains the byte-preserved legacy R2 contract.

## Shared runtime schemas

Browser-safe schemas and inferred types are exported from `src/contracts/r4/index.ts`. They import
Zod and other pure schema modules only, with no Node.js or PostgreSQL dependency.

- `CommandEnvelopeSchema`: strict `commandId`, `idempotencyKey`, `baseRevision`, and `payload`.
- `CommandResultSchema`: command/event identity, result, revision, replay flag, and warnings.
- Strict resource payload schemas are exported for every command route. Actor fields are
  never accepted; handlers derive the actor from the authenticated bearer Principal.
- `FilterNodeSchema`: strict recursive filter AST, maximum depth 5 and 50 nodes.
- `HumanWorkQuerySchema`: model, filter, search, one to three sorts, archive flag, and page cursor.
- `WorkItemCardSchema` and `WorkItemDetailSchema`: explicit-null R4 Work projections.
- `ProjectSchema`, `QuerySnapshotSchema`, and `QueryPageSchema`.

Allowed filter operations are `and`, `or`, `not`, `eq`, `in`, `range`, `is_null`, and `relation`.
Allowed fields are `spaceId`, `projectId`, `workflowStateId`, `stateCategory`, `priority`,
`accountableOwnerId`, `type`, `labelId`, `startDate`, `dueDate`, `createdAt`, `updatedAt`, and
`archived`. Sort fields are `createdAt`, `updatedAt`, `title`, `priority`, `dueDate`, and
`workflowPosition`; servers append entity ID as the final tie-breaker.

Reference-ID ranges (`spaceId`, `projectId`, `workflowStateId`, and `labelId`) compare only readable
references. Nullable reference filters also operate only on readable references, including under
negation. These semantic refinements are enforced at runtime even where JSON Schema cannot express
them.

## Command route inventory

All command routes use `POST`, `PATCH`, or `PUT` under `/api/commands/v1/workspaces/:w` and derive
the actor from bearer authentication. Creates require `baseRevision: null`; effective updates
require the current revision.

- Spaces: `/spaces`, `/spaces/:s`, `/spaces/:s/access`.
- Workflow: `/spaces/:s/workflow`, `/spaces/:s/workflow/states`, state update and state archive.
- Labels: `/spaces/:s/labels`, `/labels/:label`, and label archive.
- Projects: `/projects`, `/projects/:project`, project archive, and project restore.
- Work Items: `/work-items`, `/work-items/:item`, Work archive, and Work restore.
- Relations: `/relations`, `/relations/:relation`, and relation archive.
- Comments: `/entities/:subject/comments` and `/comments/:comment`.
- Saved Views: `/saved-views`, `/saved-views/:view`, and Saved View archive.
- ACL: `PUT /entities/:entity/access`.
- Import: `POST /imports?mode=validate|commit`.

Prefix each path with `/api/commands/v1/workspaces/:w`. Every body uses the same strict envelope:

```json
{
  "commandId": "01JCOMMAND",
  "idempotencyKey": "client-operation-42",
  "baseRevision": null,
  "payload": {
    "id": "engineering",
    "key": "ENG",
    "name": "Engineering",
    "visibility": "private",
    "description": "",
    "icon": null,
    "leadId": null
  }
}
```

Creates return `201`; effective updates return `200`. An exact idempotent replay returns `200` with
the original command and event identity and `replayed: true`. Reusing a key for a different
normalized action, route, Principal, base revision, or payload returns `409`. Stale revisions return
`409`, authorization denial returns `403`, hidden entity denial returns `404`, and malformed or
unknown fields return `400` without committing resource, revision, event, outbox, or idempotency
state.

Changing an accountable owner requires effective `work.assign` authority for the target Work Item
and its current scope. Saved View update/archive/access operations recheck authority against the
view's current Space scope, not a caller-supplied replacement scope. Switching a workflow default
creates the former default state's canonical revision/event in the same transaction; failure rolls
back both states.

```json
{
  "commandId": "01JCOMMAND",
  "eventId": "01JEVENT",
  "result": { "id": "engineering" },
  "revision": 1,
  "replayed": false,
  "warnings": []
}
```

## Human query route inventory

Human reads use `/api/human/v1/workspaces/:w`:

- `GET /bootstrap`, `/spaces`, `/spaces/:s/config`, `/projects/:p`, and `/work-items/:id`.
- `GET /entities/:id/history`, `/entities/:id/relations`, and `/entities/:id/comments`.
- `GET /saved-views`.
- `POST /projects/query`, `/work-items/query`, `/work-items/board`, `/search`, and `/export`.
- `DELETE /query-snapshots/:snapshotId` releases an owned transient snapshot and returns an empty
  `204` without disclosing absent or foreign ownership.

Paged search uses `SearchRequestPagedSchema`, including `cursor: string | null`; the earlier
limit-only `SearchRequestSchema` branch is shadowed by the composed search router. Generic entity
event replay is `GET /api/events/v1/workspaces/:w/events`. Import validation and commit share
`POST /api/commands/v1/workspaces/:w/imports?mode=validate|commit` with NDJSON bytes and required
command/idempotency headers; commit additionally requires the validation token.

Every collection, count, group, search candidate, relation endpoint, comment subject, and export
record is filtered by effective Workspace, private-Space, and restrictive entity ACL before matching,
ranking, aggregation, or limiting. By-ID denial is indistinguishable from absence.

## Persistence contract

- `005_entity_registry_acl.sql` installs all 15 permission atoms, namespaced Space entities,
  Work Item entity/revision backfill, restrictive ACL, authority epochs, and the shared SQL ACL
  predicate. Existing grants are preserved exactly.
- `006_entity_event_outbox.sql` creates the independent `entity-v1` event and delivery stream.
  Historical events create no jobs. Future legacy Work Item events atomically update the entity,
  revision, generic event, and generic outbox while retaining the old stream unchanged.
- `007_r4_pm_core.sql` adds normalized Space configuration, workflow/state, Project, Work metadata,
  labels, relations, threads/comments, Saved Views, and PostgreSQL FTS documents.
- `008_human_query_import_retention.sql` adds bounded snapshots, stable import mappings, and
  non-destructive retention policy data.
- `009_legacy_workflow_revision_history.sql` deterministically creates missing revision-1 workflow
  and five canonical workflow-state snapshots for legacy Spaces. Unresolved historical actors stay
  `NULL`, and existing later history is preserved.
- `010_legacy_work_query_projection.sql` adds a nullable, schema-tagged transient projection sidecar
  for frozen legacy Work Item query members and invalidates only incompatible transient snapshots.
  It does not rewrite legacy fingerprints, events, or revisions.

Snapshots allow at most 100,000 members, 250,000 active rows per Workspace, eight active snapshots
per Principal, and a 15-minute lifetime. Query pages are 1-100; board handlers must enforce 1-25.
Import handlers must enforce 10 MiB and 10,000 records and bind validation tokens to exact bytes.

## Compatibility, operations, and deferred work

Fresh Workspace bootstrap grants all 15 atoms. Migration never widens existing grants. Existing
members use the explicit additive `grant-r4-permissions` operator command and private Spaces still
require explicit Space grants.

Backup profiles `r3-schema-004-public`, `r4-schema-008-public-v1`,
`r4-schema-009-public-v1`, and `r4-schema-010-public-v1` retain their exact ledgers and fingerprints.
Restore upgrades every older registered profile to 010 before final validation and quarantine; old
pins remain unchanged. These bounded profiles do not provide PITR, encryption, authenticity
signatures, scheduling, replication, or full R8 operations. See the
[backup runbook](backup-recovery.md).

The local route/schema inventory test is executable evidence for API documentation freshness only.
Separate recorded evidence covers native Node 24 source loading, live export/import/archive flows,
and 11 Chrome scenarios. Final named-gate reruns at the current HEAD are pending; no recorded result
proves CI or promotes the formal R4 exit gate.
